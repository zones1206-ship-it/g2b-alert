## 11. 새 판정 안전망

`equipment_filter.classify()` 순서 — 지시문 17번의 5단계를 그대로 구현했다.

```
1. 시설·유틸리티          → 제외
2. 산업이 명백히 다른 분야  → 제외   ← 신설 UNRELATED_INDUSTRY_TERMS
3. 장비 구매가 아님이 분명  → 제외
4. 산업 확실 + 장비 확실   → 장비
5. 산업 없음 + 팹 공정 장비명 → 검토  ← 신설 STRONG_EQUIPMENT_TERMS
6. 산업 없음 + 일반 장비어  → 제외
7. 산업 없음 + 장비도 아님  → 제외
```

**2번이 5번보다 앞이다.** 장비처럼 보인다는 이유로 의료기기·항공관제를
반도체 장비로 올리지 않기 위해서다.

검토를 늘리지 않기 위해 `STRONG_EQUIPMENT_TERMS`에는 **팹 공정 장비를
특정하는 이름만** 넣었다. `장비`·`시스템`·`측정기`·`레이저`·`현미경` 같은
일반어는 넣지 않았다. 이 선 덕분에 KRISS 중적외선 레이저는 안전망에 걸리지
않고 제외를 유지한다.

3. **검토 필요 안전망의 실전 관찰.** 이번에 추가한 5번 분기는 현재
   데이터에서는 한 건도 걸리지 않았다(검토 0건). 실제로 검토가 발생하기
   시작하면 건수가 적정한지, 걸린 공고가 실제 장비인지 한 번 확인해
   `STRONG_EQUIPMENT_TERMS` 범위를 조정할 필요가 있다.

## 부록. 작업 중 잡은 자체 결함

`UNRELATED_INDUSTRY_TERMS`에 `"수의"`(수의학)를 넣었더니 정부 계약방식인
**`"소액수의계약"`·`"특정수의계약"`**에 걸려 멀쩡한 KANC 공고 3건이
"수의학 분야"로 분류됐다.

판정(제외)은 그대로여서 **판정만 비교했을 때는 드러나지 않았고, 사유까지
비교해서야** 발견했다. 한글은 부분 문자열로 맞추므로 짧은 단어를 넣으면
안 된다. 같은 이유로 `"제약"`(→ 설계 제약), `"사료"`(→ 검사료),
`"조리"`(→ 조리개)도 뺐다.

No.013의 `"모니터"` → `"모니터링"` 오제외와 같은 유형이다. 반복되는
함정이라 코드 주석에 남겼고, 이후로는 판정과 사유를 함께 비교한다.
