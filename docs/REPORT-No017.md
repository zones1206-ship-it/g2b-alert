## 부록. 2차 실행에서 잡은 결함 — 보존 로직의 재색인 중복

보존 로직이 처음 발동하면서 **중복을 만들었다.**

```
[MOFCOM] 진행 중 공고 유지: ...1bbe60c1 목록 범위 밖 / 마감 2026-09-16
```

같은 공고가 이미 새 id(`...1bbe60b1`)로 수집돼 있었다. MOFCOM은 같은 공고를
다시 색인해 id를 바꾸는 일이 있는데, 그러면 옛 id가 "목록에서 사라진 것"처럼
보여 되살아난다. **지시문 18번이 정확히 경고한 문제다.**

id뿐 아니라 `announcement_signature()`(출처·원문 제목·원문 기관·게시일·
마감일·공고유형)도 확인하도록 고쳤다. Telegram 중복 방지에 쓰는 것과 같은
기준이다. 데이터에 생긴 중복 1건도 제거했고(남긴 쪽이 원래 firstSeenAt을
보유), 3차 실행에서 재발이 없음을 확인했다.

**Telegram 오발송은 없었다** — 2차의 1건은 실제 신규 공고였고, 재색인 건은
`사이트 재색인으로 id만 바뀐 공고 1건은 알리지 않습니다` 로그대로 억제됐다.
